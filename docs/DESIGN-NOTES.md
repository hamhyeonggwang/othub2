# 공개 SaaS 디자인 개선 — 홈·탐색 화면

## 범위

2026-09-20, 기존 Next.js 운영 코드를 유지한 디자인 개선이다. 사용자의 요청에 따라 실제 Google 로그인·계정별 권한/RLS 검증은 보류한다. 로컬 가짜 DB를 사용한 회귀 검사만 계속한다.

변경 경로는 `/`, `/hub/apps`, `/hub`다. 기존 도구 상세 URL, Assess, 계정 체계, DB 스키마 및 독립 HTML 도구는 바꾸지 않는다.

## 디자인 결정

- 홈: 기존 녹색 로고를 중심으로 밝은 배경, 짙은 제목, 명확한 1차 행동을 사용한다. 훈련·평가·콘텐츠 진입을 첫 화면에 배치한다.
- 소개 중심의 긴 히어로를 실제 도구 이용으로 이어지는 구성으로 정리한다. 추천 도구 → 주제별 모음 → 이용 조건 → 문의 순서다.
- 고정된 `17개/5종` 표시는 제거한다. 실제 등록 수를 조회하지 않는 홈에서 현재 수치처럼 보이지 않게 한다. 목록의 개수는 전달된 데이터로 계산한다.
- 홈은 자동재생 동영상·패럴랙스·등장 애니메이션 없이 서버에서 바로 읽을 수 있게 한다. 기존 영상·컴포넌트 파일은 삭제하지 않는다.
- 목록: 제목/설명, 검색/조건, 결과 수, 카드, 추가 안내 순서를 통일한다. 카메라 필요 여부를 카드 진입 전에 볼 수 있게 한다.
- 콘텐츠의 외부 이동은 새 창임을 표시한다. 비어 있거나 안전하지 않은 URL은 비활성 설명 카드로 표시하며 `#` 가짜 링크를 만들지 않는다.

## 탐색 동작

- 도구 검색은 제목·설명·태그·PEO 주제를 대상으로 하며 여러 단어를 모두 포함하는 결과를 찾는다.
- 카테고리, 카메라 조건, 검색어는 함께 적용한다. 빈 결과에서 초기화할 수 있다.
- 카테고리는 기존 `?cat=` URL을 유지하며 Next.js가 지원하는 native History API로 전환한다. 추가 서버 데이터 요청 없이 반영되고 브라우저 뒤로가기가 동작한다. 링크 자체는 기존 주소를 유지한다.
- 검색어와 카메라 조건은 현재 화면 메모리에만 보관한다. 이번 변경에서 검색 로그나 추가 이용자 추적은 도입하지 않는다.
- 콘텐츠에는 전체/영상/정보와 접을 수 있는 주제 필터, 결과 수, 초기화를 제공한다.

- 단위 테스트 83개, 브라우저 테스트 10개 통과.
- 타입 검사와 Next.js 프로덕션 webpack 빌드 통과.
- 320/390/768/1440px에서 가로 넘침이 없음을 자동 확인했다.
- 홈은 JavaScript가 없어도 핵심 내용과 이동 링크가 표시된다.
- 카테고리 이동/뒤로가기 시 `/hub/apps`의 추가 RSC 요청이 없음을 확인했다.
- 데스크톱·모바일 캡처를 직접 확인했다. 목록 캡처는 3개 도구와 2개 콘텐츠를 가진 테스트 전용 데이터이며 운영 등록 현황을 나타내지 않는다.
- 실제 계정 검증, 운영 콘텐츠 전수 확인, 사용자 사용성 조사, 운영 성능 측정은 수행하지 않았다.

화면 캡처는 `test-results/design-home-1440.png`, `design-home-390.png`, `design-tools-1440.png`, `design-tools-390.png`, `design-content-1440.png`, `design-content-390.png`에 생성된다. 로컬 산출물이며 커밋하지 않는다.

## 후속 디자인: 도구 상세·My Hub

기존 Preview에 대해 사용자에게 검증 완료 확인을 받고 다음 작업을 진행했다. 이번 범위는 도구 상세(`/hub/apps/[slug]`)와 My Hub(`/me`)다.

- 도구 상세: 제목·사용 조건 → 실행 화면 → 이용 안내·북마크 → 댓글 순서. 기존 iframe 경로, 카메라 허용 조건과 전체화면 동작은 변경하지 않았다.
- 카테고리 목록으로 돌아가기와 로그인 후 해당 도구로 돌아오기를 제공한다.
- My Hub: 저장 자료·최근 평가 세션을 주 영역에, 계정·인증·관리자 메뉴를 보조 영역에 배치한다. 작은 화면에서는 한 열로 읽힌다.
- 북마크 안내의 잘못된 ‘하트’ 표현을 수정하고 빈 상태에 도구/평가 탐색 버튼을 제공한다.
- 저장한 외부 자료는 기존 목록과 같은 HTTP(S) URL 검사와 새 창 안내를 사용한다. 링크가 없거나 유효하지 않으면 클릭 가능한 가짜 링크를 만들지 않는다.
- 인증 신청, 승인 대기, 치료사·관리자 영역의 기존 역할 조건은 유지한다. 최근 평가 세션은 기존처럼 최대 3개이며 전체 개수와 표시 개수를 구분한다.
- 제목·이메일·자료명이 길어져도 줄바꿈되도록 하고, 키보드 포커스와 댓글 입력의 접근성 이름을 보완한다.
- 테스트 전용 인증 응답은 localhost 가짜 백엔드에만 있다. 실제 앱 인증·DB/RLS에 우회 코드를 추가하지 않았고 DB 스키마나 저장 기능을 변경하지 않았다.

이 변경은 아래 로그인·관리자 방문 통계 개선과 함께 통합 Preview에 반영했다. 배포 정보는 문서 마지막의 통합 Preview 기록을 참고한다.

## 로그인·관리자 방문 통계 (2026-09-21)

- 로그인: 기존 녹색 브랜드로 서비스 이용 안내와 로그인 카드를 배치하고 모바일에서는 핵심 로그인 동선을 먼저 보여준다. 공개 도구와 콘텐츠는 로그인 없이 탐색할 수 있음을 안내한다.
- `safeReturnPath`를 로그인 화면에서도 적용해 안내와 실제 서버 액션의 복귀 경로를 일치시킨다. Assess 상세와 관리자 탭 등 쿼리가 있는 주소도 해당 권한 안내를 표시한다. 로그인/콜백 액션 자체는 변경하지 않았다.
- `useFormStatus`로 Google 이동 중 표시와 중복 제출 방지를 제공한다. 오류 쿼리 문자열을 그대로 표시하지 않고 고정된 안내를 사용한다. Google OAuth 제공자·승인 정책을 변경하지 않았다.
- 관리자 공통 제목과 탭의 스타일·현재 선택 표시를 정리했다. 기존 다른 관리 탭의 조회·승인·수정·삭제 동작은 유지한다.
- 방문 탭은 선택 기간의 조회수/고유 브라우저와 전체 기간 누적 조회수를 분리한다. 인기 페이지의 막대는 목록 내 최댓값 대비 상대 길이이며 사용자 비율이나 도구 실행량으로 해석하지 않는다.
- 기존 통계 RPC 두 개를 그대로 사용하며 새 수집이나 SQL은 없다. 조회 오류 시 해당 영역에 재시도 안내를 표시하고 다른 성공한 영역은 유지한다. 실제 빈 결과는 별도 안내를 표시한다.
- 지표 설명에 쿠키 식별자·DNT·집계 누락·수집 방식 변경과 독립 도구 내부 활동 미집계의 한계를 명시한다.
- 통계 테스트는 localhost 가짜 응답(7일/30일·부분 실패·빈 결과)만 사용한다. 실제 회원·평가·방문 데이터를 내려받지 않는다. OAuth 테스트 역시 로컬 가짜 authorize 목적지에서 중단하며 실제 Google 계정에 로그인하지 않는다.

이 단계 역시 아래 기록의 보호된 통합 Preview에 반영했다. 운영 배포는 바꾸지 않았다. 다음 단계는 새 통합 Preview 검토와 정식 반영 여부 결정이다.

### 로그인·통계 로컬 확인 결과

- 단위 테스트 83개, Chromium 브라우저 테스트 25개, 타입 검사와 webpack 프로덕션 빌드 통과.
- 추가 브라우저 테스트 9개: 권한별 로그인 안내·고정 오류 안내, OAuth 이동 중 버튼 상태와 복귀 경로, JavaScript 비활성 제출/외부 복귀 주소 차단, 7일/30일 지표와 순위 동시 전환, 두 종류의 부분 조회 실패, 실제 0건, 일반회원·치료사 관리자 접근 차단, 반응형 화면.
- 320/390/768/1440px에서 가로 넘침이 없음을 확인했다. `test-results/design-login-1440.png`, `design-login-390.png`, `design-admin-visits-1440.png`, `design-admin-visits-390.png`를 직접 시각 확인했다. 모든 통계 수치는 테스트 데이터다.
- 처음의 오류 상태 검사 실패는 Next.js의 기본 접근성 알림까지 선택한 테스트 범위 문제였으며 본문으로 범위를 좁혔다. JavaScript 비활성 제출은 브라우저 라우트 대체가 아닌 로컬 가짜 서버가 OAuth 목적지 응답을 제공하도록 보완한 뒤 통과했다.
